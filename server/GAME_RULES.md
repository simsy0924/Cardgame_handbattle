# 카드게임 핸드배틀 엔진 규칙 / 카드 JSON 명세

펭귄 덱 15장을 데이터화하면서 합의한 규칙을 모은 문서. 엔진 구현 때 이 문서를 기준으로 삼는다.
마지막 장에 "아직 확인받지 못한 가정"과 "다음 덱에서 정해야 할 것"이 따로 있다.

---

## 1. 게임 기본 규칙

- 턴 구성: 드로우 단계 → 전개 단계 → 공격 단계 → 엔드 단계
- 선공 첫 턴에는 드로우가 없다.
- 일반 소환은 없다. 몬스터는 카드 효과 또는 키 카드 소환 절차로만 소환한다.
- 몬스터 존은 5칸. 소환은 빈 칸이 있어야 성공한다.
- 마법·함정 존은 없다. 일반·마법·함정 카드는 **발동과 동시에 묘지로 간다.**
- "일반 카드"는 유희왕의 일반 마법 위치다.
- 패가 비면 패배한다.
- 위치 표기가 없는 몬스터 효과는 필드에서 발동한다.

## 2. 패: 일반 패와 공개 패

- **일반 패(비공개)**: 드로우로 얻은 카드만 해당한다.
- **공개 패**: 드로우 이외의 방법으로 패에 들어온 카드 전부(서치, 되돌리기, 회수, 가져오기 등). 상대가 언제든 볼 수 있다.
- 패에 들어올 때마다 새로 공개로 들어온다(드로우 제외).
- 공개 상태는 효과로 바꾸기 전까지 계속 유지된다. 턴이 끝나도 풀리지 않는다.
- 비공개 패에서 효과를 발동하려면 먼저 그 카드를 공개해야 한다. 공개한 뒤에도 계속 공개 상태다.
- 상대가 내 패를 무작위로 버리게 할 때, 카드에 따로 적혀 있지 않으면 공개 패는 보고 고를 수 있다.
- 카드 위치 값: `hand`(공개 여부 무관), `hand_hidden`, `hand_revealed`

## 3. 키 카드

- 키 카드는 일반 덱과 별개인 **키 카드 덱**에 들어가고, 카드마다 1장씩이다.
- **가져오기**는 카드 효과가 아니라 게임 공통 행동이다.
  - 우선권이 있을 때 아무 때나 선언하고 발동할 수 있다.
  - 발동 시점에는 가져오는 카드가 공개되지 않는다.
  - 처리 시 패로 들어온다.
  - 같은 체인에 두 번 올릴 수 없고, 무효로 할 수 없다.
  - 코스트와 턴당 횟수 제한은 없다.
- 카드에 따라 가져오는 데 조건이 붙는다. 이 조건은 **가져오기 선언에만** 적용되고, 서치나 되돌리기로 패에 넣을 때는 적용되지 않는다. 카드의 `fetch.condition`에 적는다.
- "바로 사용해야 한다" 같은 제약도 `fetch.condition`의 조건으로 표현한다.
- 카드 텍스트에서 **숫자 1 앞에 있는 문장은 효과가 아니라 카드 자체의 규칙 텍스트**다. 카드 단위 필드(`fetch`, `summon_restriction`, `name_alias`)나 효과의 `limit`으로 옮긴다.

## 4. 카드 JSON 구조

항상 같은 모양을 유지한다. 해당 없는 필드도 `null`, `[]`로 명시한다. 단, 첫 처리 묶음에는 `on_prev_fail`을 쓰지 않는다.

### 카드 단위 필드

| 필드 | 설명 |
|---|---|
| `id` | `덱이름_번호` (예: `penguin_001`). 번호에 큰 의미는 없다. |
| `name` | 카드명 |
| `type` | `monster`, `normal`, `spell`, `trap` |
| `deck` | `main` 또는 `key` |
| `tags` | 분류 태그. 엔진은 카드명 대신 태그로 '펭귄' 같은 계열을 검색한다. |
| `attack` | 공격력(몬스터) |
| `name_alias` | 특정 위치에서 카드명을 다른 이름으로 취급. 예: `{ "locations": ["hand"], "as": "펭귄 용사" }` |
| `fetch.condition` | 가져오기 선언 조건. 없으면 `null` |
| `summon_restriction.only_by_effects_of` | 이 효과로만 소환 가능. 카드명 또는 카드 id 목록 |
| `effects` | 효과 목록 |

### 효과 단위 필드

| 필드 | 설명 |
|---|---|
| `id` | `e1`, `e2` … (카드 텍스트의 효과 번호) |
| `timing` | `{ turn, phase, event }` 항상 세 칸 |
| `condition` | 발동 조건. 없으면 `null` |
| `cost` | `{ pay, isTargeting, targets }` |
| `action` | 처리 묶음 목록 (또는 `repeat` 블록) |
| `continuous` | 상시 효과일 때만 사용. 이때 `timing`은 전부 `null`이고 `action`/`cost`는 없다 |
| `limit` | `{ scope: "turn" \| "game", count }` 또는 `null` |

`limit`의 공유 그룹은 기본이 `카드id:효과id`다. 효과끼리 제한을 공유하는 카드만 `group`을 직접 지정한다.

## 5. 타이밍

- `turn`: `self`, `opponent`, `both`
- `phase`: `draw`, `deploy`, `attack`, `end`, `all`
- `event`가 있으면 **유발 효과**, 없으면 **기동 효과**다. 따로 효과 종류 필드는 두지 않고 엔진이 태그로 판별한다.
- 이벤트: `summoned`, `sent_to_grave`, `effect_activated`, `would_discard`
- **타이밍이 적혀 있지 않을 때의 기본값**
  - 몬스터 효과, 일반 카드: 자신 전개 단계 → `{ turn: self, phase: deploy }`
  - 마법: `{ turn: both, phase: all }`
  - 함정: `{ turn: opponent, phase: all }`
- "상대 턴에"만 적혀 있으면 `{ turn: opponent, phase: all }`.

## 6. 코스트와 대상

- `cost.pay`에 지불 항목을 순서대로 적는다: `reveal`, `discard`, `banish`, `select`
- `reveal`의 `only_if_hidden: true`는 비공개일 때만 공개한다는 뜻이다. 이미 공개 패면 건너뛴다.
- **대상을 취하는 효과**는 `isTargeting: true`이고 `targets`에 대상을 적는다. 대상 종류(`kind`)는 `card` 또는 `effect`다.
- 처리 중에 고르는 것(비대상)은 `action`의 `select`로 처리한다. "고르고"라고만 쓰여 있고 "대상으로 하고"가 없으면 비대상이다.
- 대상을 취한 효과는 처리 전에 대상이 필드를 벗어나면 **불발**이다.
- 대상의 수치(공격력 등)를 쓰는 계산은 **처리 시점의 값**을 쓴다.

## 7. 효과 처리

### 처리 묶음 (group)

- 카드 텍스트에서 **"그 후", "추가로"가 없으면 동시처리, 있으면 비동시처리**다. 오래된 카드는 예외가 있어서 카드별로 확인한다.
- `apply: "simultaneous"`: 한 묶음 안의 처리는 취급상 동시다. 절차상으로는 순서대로 하나씩 처리한다.
  - 예: "2장 드로우한 뒤 패를 1장 고르고 버린다"는 한 묶음이다.
  - `select`(고르는 동작)는 처리 단계가 아니라 묶음 안의 절차다.
- `apply: "sequential"`: "그 후"로 이어지는 다음 묶음이다. `on_prev_fail: "stop"`이 기본이고, 앞 묶음이 실패하면 뒤는 이어지지 않는다.
- `allow_partial`: 동시처리 묶음에서 일부만 처리돼도 되는 예외 카드용. 기본은 `false`다. 모든 묶음에 명시한다.
- `optional: true`: "~할 수 있다"가 붙은 묶음. 처리하지 못해도 효과를 발동할 수 있다.

### 발동 가능 여부와 처리 중 실패

- 동시처리 묶음의 처리가 하나라도 불가능하면 발동할 수 없다(예외는 `allow_partial`).
- 비동시처리는 발동 시 **첫 묶음**이 가능한지로만 판단한다. 뒤 묶음은 처리 중에 판단한다.
- 체인 등으로 처리 중에 일부가 불가능해졌을 때:
  - 두 번째만 불가능하면 첫 번째만 처리하고 끝낸다.
  - 첫 번째가 불가능하면 불발이고 두 번째도 하지 않는다.
- 카드에 따라 위 규칙과 다른 예외가 있으면 그 카드의 묶음에 플래그로 표시한다.

### 반복 (`repeat`)

- 한 번 돌 때마다 한 번 더 할지를 발동한 플레이어가 정한다(`continue: "ask_each_loop"`). 최소 1회다.
- 도중에 막히면 반복 전체가 끝난다(`on_fail: "end_repeat"`).
- 횟수가 정해진 반복은 `rounds`를 쓴다. `per_player: true`면 각자 그 횟수만큼 하고, 순서는 `player_order`를 따른다.
- 반복이 끝난 뒤에야 그 사이에 쌓인 유발 효과가 한꺼번에 체인에 올라간다.

### 기타 처리 규칙

- 수치 변경에 기간이 적혀 있지 않으면 **영구**다. 기간이 있으면 `duration: "end_of_turn"`.
- 무효가 된 효과는 처리만 막힌다. 이미 낸 코스트는 돌아오지 않고, 무효 후 따로 묘지로 가지 않는다(마법·함정은 이미 묘지에 있다).
- `negate_effect`는 `chain.last`처럼 체인의 효과를 가리킨다. 비대상이다.
- 대체 효과("버려질 경우 대신")는 원래 처리가 일어나기 전에 끼어들어 원래 처리를 대신한다(`replaces`). "~할 수 있다"면 엔진이 발동 여부를 물어본다.

## 8. 카드명과 소환 제한

- 카드명 비교(필터, 소환 제한 등)는 **효과가 적용된 현재 이름** 기준이다.
- 마법은 발동과 동시에 묘지로 가므로, **처리 시점의 카드명**을 쓴다. 그래서 `펭귄이여 영원하라`는 1효과든 2효과든 처리 시점에는 `펭귄의 영광`으로 취급돼서, `펭귄의 영광`의 효과로만 소환할 수 있는 카드(`펭귄 용사`, `펭귄의 전설`)를 소환할 수 있다.
- "카드 A의 효과로 묘지로 보내졌을 경우" 같은 감지를 위해 묘지로 보낼 때 원인(`cause`: `카드id:효과id`)을 이벤트에 싣는다. 이벤트 필터는 카드 단위(`cause_card`)로도 비교한다.
- 같은 이름의 카드 여러 장은 각각 다른 실물이다. `exclude`는 이름이 아니라 실물 기준이다.

## 9. 지속 효과

- 발동하지 않고 상시 적용되는 효과는 `continuous`에 적는다. `timing`은 `{ turn: null, phase: null, event: null }`이다.
- `condition`은 이 효과가 적용되는 동안의 조건이다(예: `card_location: "field"`).
- 지금 쓰는 종류: `immunity` (`from`: 영향을 주는 쪽, `except`: 예외)
  - 예: `펭귄의 전설` 3효과는 대상으로 하지 않는 상대 카드 효과를 받지 않는다.

## 10. 액션(step) 목록

| type | 주요 필드 | 설명 |
|---|---|---|
| `select` | `id`, `from`, `filter`, `count`, `chooser`, `exclude`, `unique_by_name` | 카드 고르기(비대상). `count`는 숫자 또는 `{min, max}`. `all_possible`도 쓴다 |
| `summon` | `card`, `from`, `field` | 소환. `field: "self"`는 자신 필드 |
| `add_to_hand` | `card`, `from` | 패에 넣기(공개 패로 들어간다) |
| `draw` | `player`, `count` | 드로우(일반 패로 들어간다) |
| `discard` | `card` | 패에서 버리기 |
| `send_to_grave` | `card`, `cause` | 묘지로 보내기 |
| `banish` | `card` | 제외 |
| `return_to_hand` | `card` | 소유자의 패로 되돌리기(공개 패) |
| `return_to_deck` | `card` | 덱으로 되돌리기 |
| `reveal_hand` | `player`, `scope` | 패 공개 |
| `modify_attack` | `card` 또는 `scope`+`filter`, `amount`, `duration` | 공격력 변경 |
| `negate_effect` | `effect` | 효과 무효 |

수식 값: `{ "op": "half_ceil", "of": ... }`, `{ "op": "sub", "a": ..., "b": ... }`, `{ "count_of": "s1" }`, `{ "effect_applied_count": { card_id, effect, scope } }`, `{ "stat": "draws_this_turn", "player": "self" }`

엔진은 턴 동안 다음을 기록해야 한다: 효과 적용 횟수, 이번 턴 드로우 매수, 이번 턴에 어떤 효과로 묘지에 간 카드 목록.

## 11. 아직 확인받지 못한 가정

내가 정해서 쓴 것이라 틀렸으면 고쳐야 한다.

- 대체 효과의 구조(`would_discard` 이벤트, `replaces`)는 내가 설계했다.
- `limit` 그룹을 `카드id:효과id`로 기본 지정하는 규칙. 카드명이 같아서 제한을 공유하는 경우는 `group`을 직접 지정한다.
- `modify_attack`의 `scope`/`filter`로 필드의 여러 몬스터를 한 번에 바꾸는 표기.
- 가져오기 선언이 체인에 올라가는 정확한 시점과 우선권 규칙.

## 12. 다음 덱에서 정해야 할 것

- 효과 텍스트 자체를 바꾸는 효과 (요그 소토스, 니알라토텝): 효과를 객체로 들고 있어야 한다.
- 카운터 시스템 (엘리멘츠): 종류별 카운터 저장, 공격력 반영, 소환시 효과를 다른 카드 효과로 쓰기.
- 코인 토스: 멀티플레이 동기화를 위해 서버나 호스트에서 결정.
- 키 카드의 소환 조건 (서커스메어, 엘리멘츠 궁극신 계열): 코스트로 몬스터를 보내거나 제외했을 때만 키 카드 덱에서 소환.
- 룰상 다른 카드명으로 취급하는 것: "룰상 '서커스메어' 카드로도 취급한다".
- 체인과 우선권의 세부 규칙, 전투(공격 단계) 규칙, 승리 조건의 세부.

## 13. 범용카드에서 추가된 스키마 (generic_deck.json)

카드 필드
- `pool:"generic"` 범용 카드 표시. `deck`는 main/key 그대로.
- `fetch.forbidden:true` 패로 가져올 수 없음.
- `summon_procedure` 키 덱 소환 절차(자신 전개 단계, 체인 안 탐, 소환 무효 카드 외엔 무효 불가). pay 항목에 `constraint:{sum:"attack",op:">=",value:10}` 가능. 소환 후 summoned 이벤트는 정상 발생.
- `activation_zone:"field_zone"` 필드 카드(타이밍 기본값은 일반 카드와 같은 자신 전개 단계, 필드 존 1칸/플레이어, 새로 발동하면 기존 카드는 묘지).
- `passive` 1. 앞의 룰 텍스트(효과 외). 예: 묘지에서 대상 불가 + 자신 이외 모든 카드 효과 면역.
- 최상위 `effect_filters`: 이름 붙인 효과 성질 필터(`deck_access`). 발동한 효과의 스텝을 정적 분석해서 판정(드로우도 "덱에서 패에 넣음"에 포함).

효과 필드
- `mandatory` ("발동한다"=true, "발동할 수 있다"=false). 모든 효과에 필수.
- limit `group:"card_id"` ("이 카드명의 카드는 1턴에 1장").

이벤트: `moved_to_zone{to:[...]}`, `sent_to_grave{reason:"discard"}`, `added_to_hand{by,from}`, `attack_declared{by}`, `summoned{by,from}`.
조건: `expr.compare`, `count:"own_hand"`, 참조 `event.attacker`/`event.target`.
스텝: `restrict`(add_to_hand_from_deck/banish, 이번 턴 서로), `disable_effects`(기간 end_of_turn), `register_effect`(이번 턴 한정 임시 유발 효과, 출처는 발동한 카드), `set_battle_damage`.
참조/위치: `chain.last.source`, `deck_top`, `field_all`, `opponent_hand`, cost `return_to_deck`.
필터: `not_card_id`, 이펙트 필터 `card_name`/`includes_any`/`ref`.

확정 규칙: 드로우는 "덱에서 패에 넣는다"에 포함. 전투 데미지 = 공격력 차만큼, 공격력이 더 낮은 쪽이 패를 버림(공격한 쪽이 져도 공격한 쪽이 버림). 무효로 하고 ~하는 효과는 이미 묘지에 있는 카드라도 무효는 적용(allow_partial).

잔존 효과(restrict, register_effect, disable_effects): 처리된 뒤 턴 종료까지 남는 효과. 체인을 만들지 않고, 발동 시점(체인 링크)에 무효시키지 않으면 그 턴엔 막을 수 없음. 같은 종류의 다른 부정형 잔존 효과(예: 서치 봉인의 항아리의 덱 서치 금지)가 위에 덮어씌워 결과를 막는 것은 가능. register_effect의 효과는 `uses_chain:false`로 조건이 되면 즉시 처리.
disable_effects: 대상 카드의 효과를 턴 종료까지 무효. 이미 체인에 올라가 있는 그 카드의 효과도 처리 시 무효(자물쇠가 나중에 올라가 먼저 처리되므로).

## 14. 엔진에서 확인된 규칙 해석 (run_generic_test.mjs)
- 키 카드 소환 절차: 체인 없이 즉시. 코스트로 묘지에 간 카드의 "묘지로 보내졌을 경우" 유발은 정상 발동(예: 펭귄 용사 e3).
- 전투: 공격 선언 -> 체인/유발 창 -> 공격력 비교 -> 낮은 쪽이 차이만큼 패 버림. 진 쪽(공격력이 낮은 쪽) 몬스터는 묘지로 감(공격력이 같으면 서로 묘지로, 단 둘 다 0이면 그대로). 몬스터마다 턴에 1번 공격.
- 구사일생의 "자신 패의 수"는 발동 조건을 판정하는 시점(이 카드가 아직 패에 있을 때) 기준.
- 필드 카드: 필드 존에 놓이고, 새 필드 카드가 발동하면 기존 카드는 묘지로.
- 잔존 효과(restrict/disable_effects/register_effect)는 턴이 바뀔 때 전부 해제.

직접 공격(상대 필드에 몬스터가 없을 때): 데미지 = 공격력만큼 상대가 패를 버림(확정).
구사일생처럼 데미지를 0으로 해도 진 쪽 몬스터는 묘지로 감(임시 해석, 미확정).
미정: 공격 대상 선택 규칙, 직접 공격과 몬스터 공존 시 규칙.
